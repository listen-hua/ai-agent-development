0. 使用说明与上线原则

生产部署不是把开发地址从127.0.0.1改成服务器IP。它同时涉及镜像可追溯、Secret稳定、数据持久化、HTTPS、出网白名单、平台配置、备份恢复和权限初始化。

确定方案

单机Compose

一台Linux服务器承载应用和数据，公司网关提供HTTPS，符合当前1–2台服务器规模。

确定方案

全新生产数据

不复制开发账号、历史会话和画布，组织、知识和配置在生产重新初始化。

重要边界

不是高可用

单机故障需要从备份恢复。本文通过备份和演练降低风险，不承诺零停机。

上线角色分工

2.4 DNS、证书与网关

nslookup <公司域名>
openssl s_client -connect <公司域名>:443 -servername <公司域名> </dev/null 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
curl -I http://<应用服务器IP>:8088/
upstream shimmer_web {
    server <应用服务器IP>:8088 max_fails=3 fail_timeout=10s;
    keepalive 32;
}
server {
    listen 443 ssl http2;
    server_name <公司域名>;
    ssl_certificate /etc/nginx/certs/shimmer.crt;
    ssl_certificate_key /etc/nginx/certs/shimmer.key;
    client_max_body_size 32m;
    location / {
        proxy_pass http://shimmer_web;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 600s;
        proxy_send_timeout 600s;
        add_header X-Accel-Buffering no always;
    }
}
同源要求页面与API必须使用同一HTTPS域名。分域部署会导致IAM Cookie、Session、图片资源和SSE跨域问题。

3. Harbor 镜像构建与发布

生产只拉取固定版本，不在生产服务器编译源码。Backend镜像同时供API和Worker使用。

3.1 构建并推送业务镜像

docker login registry.shimmer.lab
export VERSION=v1.0.0
export REPO=registry.shimmer.lab/middle-office/ai-office-assistant

docker build --pull -f backend/Dockerfile -t ${REPO}:backend-${VERSION} backend
docker build --pull -f frontend/Dockerfile -t ${REPO}:web-${VERSION} frontend

docker buildx imagetools inspect ${REPO}:backend-${VERSION}
docker buildx imagetools inspect ${REPO}:web-${VERSION}

4. 生产 Compose 与环境变量

不要直接运行开发Compose仓库当前docker-compose.yml包含开发默认数据库密码、MinIO凭证、本地构建和MinIO控制台端口映射。生产使用独立文件。

4.1 可复制的生产Compose

# /opt/shimmer/docker-compose.prod.yml
name: shimmer

x-logging: &default-logging
  driver: json-file
  options:
    max-size: "20m"
    max-file: "5"

services:
  postgres:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:dependency-pgvector-pg17
    environment:
      POSTGRES_DB: ai_agent
      POSTGRES_USER: ai_agent
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:?POSTGRES_PASSWORD is required}
    volumes:
      - /data/shimmer/postgres:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ai_agent -d ai_agent"]
      interval: 5s
      timeout: 3s
      retries: 30
    restart: unless-stopped
    logging: *default-logging

  migrate:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:dependency-pgvector-pg17
    entrypoint: ["/bin/sh", "/ops/migrate.sh"]
    environment:
      PGPASSWORD: ${POSTGRES_PASSWORD:?POSTGRES_PASSWORD is required}
    volumes:
      - ./backend/migrations:/migrations:ro
      - ./ops/migrate.sh:/ops/migrate.sh:ro
    depends_on:
      postgres:
        condition: service_healthy
    restart: "no"
    logging: *default-logging

  redis:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:dependency-redis-7.4-alpine
    command: redis-server --appendonly yes
    volumes:
      - /data/shimmer/redis:/data
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 30
    restart: unless-stopped
    logging: *default-logging

  minio:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:dependency-minio-2025-04-22
    command: server /data --console-address :9001
    environment:
      MINIO_ROOT_USER: ${MINIO_ACCESS_KEY:?MINIO_ACCESS_KEY is required}
      MINIO_ROOT_PASSWORD: ${MINIO_SECRET_KEY:?MINIO_SECRET_KEY is required}
    volumes:
      - /data/shimmer/minio:/data
    restart: unless-stopped
    logging: *default-logging

  tika:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:dependency-tika-3.2.3.0-full
    restart: unless-stopped
    logging: *default-logging

  clamav:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:dependency-clamav-1.4
    volumes:
      - /data/shimmer/clamav:/var/lib/clamav
    restart: unless-stopped
    logging: *default-logging

  api:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:backend-${SHIMMER_VERSION:?SHIMMER_VERSION is required}
    env_file:
      - /etc/shimmer/shimmer.env
    depends_on:
      postgres:
        condition: service_healthy
      migrate:
        condition: service_completed_successfully
      redis:
        condition: service_healthy
    expose: ["8080"]
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1:8080/healthz"]
      interval: 15s
      timeout: 5s
      retries: 10
    restart: unless-stopped
    logging: *default-logging

  worker:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:backend-${SHIMMER_VERSION:?SHIMMER_VERSION is required}
    entrypoint: ["/app/worker"]
    env_file:
      - /etc/shimmer/shimmer.env
    depends_on:
      postgres:
        condition: service_healthy
      migrate:
        condition: service_completed_successfully
      redis:
        condition: service_healthy
    restart: unless-stopped
    logging: *default-logging

  web:
    image: registry.shimmer.lab/middle-office/ai-office-assistant:web-${SHIMMER_VERSION:?SHIMMER_VERSION is required}
    depends_on:
      api:
        condition: service_healthy
    ports:
      - "${WEB_BIND_ADDRESS:-0.0.0.0}:8088:80"
    healthcheck:
      test: ["CMD-SHELL", "wget -q -O /dev/null http://127.0.0.1/"]
      interval: 15s
      timeout: 5s
      retries: 10
    restart: unless-stopped
    logging: *default-logging
端口绑定WEB_BIND_ADDRESS填写应用服务器固定内网IP。再由主机防火墙限制只有公司网关能访问8088；不要填127.0.0.1，否则远端网关无法连接。

  1. 创建“微光 AI Agent”应用。
  2. page_url设置为https://<公司域名>/?app_id=<IAM_APP_ID>。
  3. api_url设置为https://<公司域名>。
  4. 将域名加入IAM Cookie与微前端可信域。
  5. 给普通员工至少授予agent_use。

5.3 飞书自建应用

网页与机器人

  • 启用网页应用和机器人。
  • 工作台及OAuth重定向使用生产HTTPS域名。
  • 正式版本可见范围覆盖目标员工。

长连接事件

  • im.message.receive_v1
  • card.action.trigger
  • meeting_room.meeting_room.status_changed_v1
  • 需要时添加通讯录用户变更事件。

核心权限包括：机器人收发消息和更新卡片；用户/部门信息读取；云空间、Docx、Wiki和文件读取；vc:room:readonly、calendar:room:readonly；日历、日程增删改查和忙闲读取。

无需公网回调API/Worker主动建立飞书WebSocket长连接，只需出站WSS。长连接模式不使用FEISHU_VERIFICATION_TOKEN和FEISHU_ENCRYPT_KEY。

7. 上线验收清单

勾选状态只保存在当前浏览器。正式结果还应归档到公司变更单。

基础与安全

  • HTTPS、证书链和内部DNS在浏览器及飞书客户端均正常。
  • 只有公司网关能访问应用服务器8088。
  • 员工网无法访问5432、6379、9000、9001、9998和3310。
  • APP_ENV=production且DEV_AUTH_ENABLED=false。
  • 配置、日志和前端产物中无明文App Secret或API Key。
  • 重启整机后容器恢复且PostgreSQL、MinIO数据仍存在。

身份与权限

  • IAM登录与飞书免登命中同一内部用户UUID。
  • 普通员工菜单、管理员菜单和API权限一致。

  • 至少两名用户具备user_manage，Bootstrap配置已清空。

知识、Agent与飞书

行政业务

8. 备份、恢复与灾难演练

8.1 备份范围

对象重要性建议
PostgreSQL最高：业务、向量、任务、权限、审计pg_dump -Fc每日及升级前
MinIO最高：制度、生成图、预览和抠图文件快照或tar，与数据库时间点接近
生产Secret最高：会话和后台凭证解密公司密钥系统或加密离线副本
Compose/迁移/镜像清单高：重建同版本环境Git Tag、发布包、Harbor Digest
Redis低：缓存和短期状态通常不作为灾备真源
ClamAV病毒库低恢复后重新更新

8.2 使用现有脚本

cd /opt/shimmer
export COMPOSE_FILE=/opt/shimmer/docker-compose.prod.yml
export COMPOSE_ENV_FILES=/etc/shimmer/shimmer.env

sh ops/backup.sh /backup/shimmer/$(date +%Y%m%d-%H%M%S)
find /backup/shimmer -type f -mtime -1 -exec sha256sum {} \; \
  > /backup/shimmer/latest.sha256
脚本限制当前ops/backup.sh只导出PostgreSQL、MinIO并复制.env.example，不会备份/etc/shimmer/shimmer.env。真实Secret必须走独立的公司密钥备份流程，不能复制到公共NAS。

8.3 建议周期

  • 每日：PostgreSQL逻辑备份，保留14天。
  • 每周：PostgreSQL + MinIO一致性全量，保留8周。
  • 每月：加密归档到异机或NAS，保留12个月或依合规策略。
  • 每次发布前：额外创建带版本号的即时备份。
  • 每季度：在隔离主机完成一次真实恢复演练。

8.4 隔离恢复演练

  1. 准备与生产隔离的主机和空数据目录，禁止连接正式飞书/IAM应用。
  2. 部署备份记录中的镜像和Compose。
  3. 恢复同一份AGENT_SECRET_ENCRYPTION_KEY，其他外部密钥使用测试值。
  4. 停止API和Worker，只保留PostgreSQL、MinIO。
  5. 执行恢复，再运行完整迁移。
  6. 启动应用，验证用户、文档版本、引用、画布、加密凭证状态和审计。
  7. 记录实际RTO和可恢复到的时间点RPO。
# 仅限隔离恢复环境
export COMPOSE_FILE=/opt/shimmer/docker-compose.prod.yml
export COMPOSE_ENV_FILES=/etc/shimmer/shimmer.env
docker compose stop api worker web
sh ops/restore.sh /backup/shimmer/<备份目录>
docker compose run --rm migrate
docker compose up -d api worker web
恢复具有破坏性restore.sh会清理目标数据库对象并执行rm -rf /data/*清空MinIO容器数据。没有确认服务器、Compose项目、备份目录和维护窗口时绝对不要执行。

9.2 回滚原则

  • 只有应用问题且迁移向后兼容：把SHIMMER_VERSION改回旧版本并重建API、Worker、Web。

10. 当前项目部署边界

健康检查/healthz主要证明Go进程存活，不会完整检查PostgreSQL、Redis、MinIO、Tika、ClamAV、IAM、飞书和模型。
OCR配置保留OCR_URL，但当前Compose没有PaddleOCR。扫描PDF或纯图片制度可能无法提取文字。
单机Compose能重启进程，不能抵御主机、数据盘或机房故障。恢复能力取决于异机备份。
外部服务飞书、IAM、百炼、中转站或Pixian不可用时对应功能失败或降级，但本地已有数据不会自动丢失。

何时升级架构

  • 业务要求RTO小于30分钟、RPO接近0。
  • API和Worker需要跨主机滚动发布或独立扩容。
  • 单机磁盘无法承载图片，需要MinIO集群或公司对象存储。
  • PostgreSQL需要主备、连接池和独立运维。
  • 并发持续超过当前30路基线，后台任务开始影响问答。

达到这些条件时，优先外置PostgreSQL和MinIO并拆分应用与数据，再评估Kubernetes。
